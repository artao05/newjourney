## Questions for you

1. **D7, Expedition itself,** is still what would help most:
   - **Last tick's two start items.** 5.6 (the top-corner time) and 5.7 (time to layline,
     the pinch times, boat to pin and gun speed as a percentage of target) still need
     checking against the program.
   - **Expedition's own CSV log layout,** so its logs import as they are.
   - **Its channel numbering,** so the text protocol's data lines can be named.
2. **A real boat, or a recording from one.** Signal K, serial NMEA 0183 and NMEA 2000 are
   tested only against recorded streams and mocked ports. A Signal K server, or an NMEA
   log from a boat, would test them for real. If you have one, the new log import
   already reads NMEA recordings.
3. **The forecast hit Open-Meteo's daily limit today.** During testing the marine layer
   came back "Daily API request limit exceeded". On race day that would leave routing
   with wind only. It strengthens the case for **D1**, the small backend: it would cache
   forecasts, so each device doesn't spend its own quota.
4. **D3, transmitting to instruments,** still blocks 6.10. It also means the text
   protocol's replies (ACKs and mark queries) are built but not sent.
5. **Readings I chose. Please say if any is wrong:**
   - **Phone compass:** trusted only below 10° reported accuracy, which only iOS reports.
   - **Replay time:** replayed fixes are stamped with the present time, so no screen calls
     them stale. The log's own time shows on the playback bar, but the TIME box shows
     the real clock.
   - **GPS lost:** the alarm fires when there has been no fix at all, not only when a fix
     goes quiet.
   - **Grid router:** forward-only moves box it in among Casco Bay's islands, and its
     error message says so. It is meant as a second opinion in open water.
